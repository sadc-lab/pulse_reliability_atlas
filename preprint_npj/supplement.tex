\section{Pulse engine in context}\label{sec:s1}

The Pulse Physiology Engine~\cite{bray2019} is among the most actively maintained open-source whole-body human physiology simulators. It represents the body as a network of coupled electrical-circuit analogues --- vascular resistances as resistors, vessel and chamber compliances as capacitors, heart and respiratory muscles as time-varying pressure sources --- solved as a system of ordinary differential equations at a 20~ms fixed timestep. The cardiovascular, respiratory (a 5-compartment lung model: carina, left and right anatomic dead space, left and right alveoli), gas-exchange, endocrine, renal, and drug sub-models share state at each step, producing a self-consistent whole-body trajectory in roughly 10--15$\times$ real time on commodity hardware. The codebase is C++ with bindings for Python, Java, C\#, and Unity, and runs on Windows, Linux, macOS, Android, iOS, and ARM.

Pulse was forked in 2017 from the U.S.\ Department of Defense--funded BioGears engine by the original BioGears core developers (Clipp, Bray, Webb) and is now maintained by Kitware, Inc.\ under the Apache-2.0 license. Both projects still exist independently but have diverged substantially since 2017; Pulse v4.3.1 includes respiratory calibration for ventilated patients, mechanoreceptor feedback, lung-recruitment modelling, and improved hemorrhage response that are not present in BioGears.

The Pulse documentation explicitly characterises the engine as a ``low-fidelity clinical approach'' intended for training simulation rather than patient-specific clinical prediction. This self-description frames the present atlas's contribution (Section~1 of the main manuscript): a quantitative operational-envelope reliability map that lets downstream users decide where Pulse's low-fidelity clinical approach is in fact reliable for their use case and where it is not. The current upstream stable head is \texttt{REL\_4\_3\_2} (released 2025-08-12), whose full diff against \texttt{REL\_4\_3\_1} is build-system-only (7 files / +46 / -17 lines: web-WASM dockcross support and a .NET binding tweak); no physiology, validation, patient-setup, or solver code changed. Results in this atlas on v4.3.1 therefore apply identically to v4.3.2.

\section{Full Methods detail}\label{sec:s3}

This section expands the condensed Methods section of the main manuscript (Section~4 of the main manuscript) with the engine-wrapper architecture, the deterministic Docker recipe, the complete physiological-bounds and drift-threshold tables that anchor the four-flag steady-state classifier, the input-rejection regex set used to detect Pulse's setup-time clamping, and the body-dimension provenance for the two adult reference patient bodies.

\subsection{Engine wrapper, Docker pinning, and reproducibility}\label{sec:s3-engine}

The atlas wrapper is a thin Python orchestration layer around Pulse's command-line interface. For each Morris input vector, the wrapper writes a JSON configuration file (patient reference body, ARDS scenario condition, ventilator action set, and the seven operational inputs at their Morris values), spawns a Pulse Docker container against the pinned \texttt{pulse-atlas-engine} image, captures the resulting steady-state CSV plus the engine setup log, and emits a per-run aggregated row into the canonical parquet. The wrapper is deterministic given the same input vector and the same Docker image; bit-exact reproduction of the canonical 1{,}280-run sweep was verified at three independent layers (the canonical Morris sample regenerated from the SALib seed, the per-cell aggregate parquets, and the derived statistical artefacts). The full Docker invocation template, including the safety caps on memory and CPU and the path-conversion handling required on Git Bash under Windows, is documented in the companion code repository.

\subsection{Morris sampler implementation}\label{sec:s3-morris}

The Morris elementary-effects sample is generated by SALib's \texttt{morris.sample}~\cite{iwanaga2022} with 20 trajectories, 4 grid levels per input, and random seed 42 (the canonical sweep constants \texttt{SWEEP\_TRAJECTORIES}, \texttt{SWEEP\_LEVELS}, \texttt{SWEEP\_SEED} in \texttt{scripts/run\_full\_sweep.py}; see audit-ledger entries \texttt{T1.06e}, \texttt{T1.06f}, \texttt{T1.06g}). Each trajectory contributes $(\text{num\_inputs} + 1) = 8$ model evaluations along a one-at-a-time perturbation path through the 7-dimensional input space, yielding 160 model evaluations per (scenario, sex) cell and 1{,}280 evaluations across the full sweep. The seven input ranges (heart rate 50--110~bpm, systolic blood pressure 90--120~mmHg, diastolic blood pressure 60--80~mmHg with the post-clip pulse-pressure ratio DBP/SBP $\leq 0.75$ enforced, respiratory rate 8--20~bpm, tidal volume 300--800~mL, inspired oxygen fraction 0.21--1.0, and positive end-expiratory pressure 0--20~cmH$_2$O) match Pulse's verified setup-time acceptance bands so that the sampler never proposes inputs outside Pulse's accepted envelope.

\subsection{Sobol bolt-on: preregistered decision}\label{sec:s3-sobol}

A second-tier variance-based analysis (Sobol) was preregistered as a conditional bolt-on on top of the Morris main-effect screening. The promotion rule, locked in \texttt{preregistration.md}~\S~Sampling method, fires on any cell whose dominant input exhibits a $\sigma / \mu^{*} \geq 0.6$ point estimate --- the $\sigma / \mu^{*}$ ratio being the standard Morris proxy for non-linearity and input-input interaction. Applied to the dominant input per (scenario, sex, output) cell, the point estimate fires the trigger on 8 of 48 cells. Two of these are SpO$_2$ in healthy patients ((S1, F, SpO$_2$, PEEP); (S1, M, SpO$_2$, Vt)), where the dominant input's $\mu^{*}$ sits at numerical-noise level because the output is pinned at the hemoglobin-saturation ceiling --- the high $\sigma / \mu^{*}$ ratio is mathematically real but physiologically empty. The remaining six are non-linearities established a priori by respiratory physiology: the four FiO$_2~\rightarrow$~PaO$_2$ cells in mild and moderate ARDS (S2 and S3, both sexes) where venous admixture caps oxygenation gain per FiO$_2$ increment, and two minute-ventilation cells coupling RR or Vt to PaCO$_2$ via the alveolar-ventilation identity $\dot{V}_A = \mathrm{RR} \cdot (V_T - V_D)$.

CI-aware re-evaluation of the trigger sharpens the picture. Resampling trajectories (block bootstrap, 1{,}000 resamples, identical RNG seed to the $\mu^{*}$ CI) and recomputing $\sigma / \mu^{*}$ per resample distributes the 48 cells into four buckets: \emph{CI-robustly linear} (upper bootstrap bound on $\sigma / \mu^{*}$ strictly below 0.6) on 31~/~48 cells (65~\%); \emph{straddling 0.6} on 12~/~48 cells; \emph{no estimable CI} (only a single clean trajectory pair on the dominant-input edge) on 5~/~48 cells; and \emph{CI-robustly non-linear} (lower bootstrap bound on $\sigma / \mu^{*}$ at or above 0.6) on 0~/~48 cells.

The Sobol bolt-on is therefore closed by evidential redundancy, not by compute shortage. The preregistered trigger was designed to flag cells whose non-linearity is evidentially established, not cells whose point estimate merely happens to land above threshold; zero cells clear that evidential bar. Running variance decomposition on bootstrap-borderline cells would re-derive an already bootstrap-noise-dominated ranking, and the six physiologically-driven cells in the point-estimate set are qualitatively recovered by the Morris main-effect rankings reported in Section~2.2 of the main manuscript. A ready-to-fire SALib implementation ($N = 256$, six target cells, $\sim$~14~k Pulse runs, cluster-friendly) is preserved in the released code base for reviewers or practitioners who want the variance decomposition anyway.

\subsection{Four-flag classifier: priority order and rationale}\label{sec:s3-detector-order}

The detector's flag priority order \texttt{clamped > diverged > implausible > not\_steady\_state > clean} traces the chronology of failure modes a Pulse simulation can exhibit, from input handling through solver execution to output evaluation against biological and dynamic criteria. \texttt{clamped} is the input-contract breach: Pulse has silently substituted at least one setup input, so the simulation no longer corresponds to the Morris grid point that was requested and no downstream flag would refer to the input being studied --- disqualifying the run at this layer is non-negotiable. \texttt{diverged} is the mathematical failure: a non-zero exit code, NaN or infinite values in the CSV, a missing CSV, or a truncated simulation --- no biological interpretation is possible. \texttt{implausible} is the biological failure: the mathematics ran cleanly but the steady-state mean falls outside the hard physiological bounds in Table~\ref{tab:hard-bounds} --- mathematically valid output, biologically incompatible with a viable 60-second steady-state. \texttt{not\_steady\_state} is the dynamic failure: the output is mathematically valid and biologically coherent but the trajectory has not settled in the 60-second window (flatline at a bound, coefficient of variation above 0.05, or drift exceeding the per-channel thresholds in Table~\ref{tab:drift}) --- the result is interpretable as a transient, not as steady-state physiology.

\subsection{Drift thresholds for the not\_steady\_state flag}\label{sec:s3-drift}

The companion \texttt{DRIFT\_MAX\_DELTA\_60S} dictionary (Table~\ref{tab:drift}) sets the per-channel maximum tolerated $|\Delta| = |\text{slope} \times 60~\text{s}|$ that an output may exhibit across the final 60 seconds of the steady-state window before the run is flagged \texttt{not\_steady\_state} for drift. Drift is estimated by ordinary least-squares regression on the 13 sample points in the [60, 120]~s window (5-second sample interval); the $R^2$ of the fit is logged as diagnostic metadata but does not gate the flag. These thresholds are clinical-meaningfulness anchors --- beyond them, a bedside clinician would read the trajectory as actively changing rather than at homeostasis. Unlike the hard bounds in Table~\ref{tab:hard-bounds}, they are atlas-internal calibration choices rather than biological survival limits; the per-channel magnitudes are anchored in standard critical-care monitoring practice (Table~\ref{tab:drift-rationale}) rather than in mortality-incompatibility primary literature, and the citations in Table~\ref{tab:drift-rationale} identify the relevant clinical-monitoring framing rather than primary-literature endorsements of the specific drift magnitudes. Like the hard bounds, each value is regex-extracted from \texttt{src/detector.py} at audit time.

Two further \texttt{not\_steady\_state} triggers complement the drift check. The coefficient-of-variation threshold \texttt{CV\_THRESHOLD = 0.05} fires when the standard deviation of any output across the steady-state window exceeds 5~\% of its mean. The flatline-at-bound criterion fires when \texttt{std / |mean| < 0.01} AND the mean is within 0.1~\% of a hard bound, distinguishing numerical pinning at a bound from physiological saturation at that bound. Both constants are recorded in the companion code repository and are locked under the same preregistration discipline as the bounds and drift thresholds.

\subsection{Clamp regex set}\label{sec:s3-clamp}

The \texttt{clamped} flag fires when Pulse's setup-rejection log matches any of the following four regular-expression patterns. Each pattern targets one observed Pulse rejection message and was empirically calibrated against deliberate-clamp probes in the pilot study before the full sweep launched, replacing an earlier overly-broad regex set that produced 100~\% false-positive clamping by matching Pulse's normal solver convergence messages:

\begin{lstlisting}[basicstyle=\ttfamily\small, breaklines=true]
r"baseline of [\d\.]+ \S+ is too (?:high|low)"
r"maximum [\w\s]+ baseline allowed is"
r"must be modeled by adding/using a condition"
r"is outside the valid range"
\end{lstlisting}

\section{ARDS impairment-fraction instability zone}\label{sec:s5}

Section~2.6 of the main manuscript refers to a documented 0.91--0.945 ARDS-impairment-fraction band in which Pulse's respiratory solver becomes unstable. This supplement section provides the full characterisation: how Pulse translates the single impairment-fraction scalar into respiratory-mechanics and gas-exchange changes, how the band was identified, how the present atlas's continuous-severity micro-sweep refines its edges, and how the divergence rate within the band stratifies by sex under midrange Morris inputs.

\subsection{Severity-to-physiology mapping in the Pulse respiratory model}\label{sec:s5-mapping}

Pulse represents ARDS as a single \texttt{Severity} scalar in $[0, 1]$ per lung compartment (the \texttt{AcuteRespiratoryDistressSyndrome} condition); the atlas sets it bilaterally and symmetrically to the scenario impairment fraction (left lung = right lung). That one scalar is fed independently into four hard-coded piecewise-linear interpolation curves in the respiratory-model source (\texttt{RespiratoryModel.cpp}: \texttt{UpdateResistances}, \texttt{UpdateAlveolarCompliances}, \texttt{UpdateDiffusion}, and \texttt{UpdatePulmonaryShunt}), each calibrated against the adult standard patient; there is no independent handle on resistance, compliance, or diffusion. Table~\ref{tab:s5-mapping} reports the resulting multipliers at the three ARDS scenario severities, linearly interpolated from the source calibration nodes.

The four curves act in concert: at S4 (impairment 0.95) Pulse multiplies distal alveolar resistance by $\approx 22\times$, cuts alveolar compliance to $\approx 45\,\%$ of baseline, collapses the alveolar diffusion surface area to $\approx 7.5\,\%$ of baseline, and opens the intrapulmonary shunt. The diffusion-surface collapse together with the widened shunt is the proximate driver of the severe arterial hypoxemia behind the input-HR / output-HR decoupling reported in main-manuscript Section~2.6. The shunt row is the least direct of the four: its damage term is non-monotonic across severity and is combined by a \texttt{MIN} operation with an alveolar-recruitment term (a function of actual alveolar volume, which PEEP raises) and a left/right calibration factor, so the effective shunt resistance is not simply the tabulated damage multiplier. Severity additionally feeds the respiratory driver pressure, lung volumes, and the inspiratory:expiratory ratio through smaller restrictive terms. The four curves are themselves smooth; the 0.91--0.945 solver-instability band characterised below is an emergent numerical property of the combined stiff respiratory state, not a discontinuity in any single curve.

\textbf{Forward-looking limitation (pediatric and neonatal).} Both the baseline resistance, compliance, and diffusion-surface values \emph{and} the severity-to-effect curves above are tuned to the adult standard patient, and the single-scalar design forbids retuning the three properties independently. Carrying these settings to pediatric mechanics --- where compliance per kilogram, airway resistance, and absolute gas-exchange surface differ substantially --- would mis-scale the absolute consequences, which is one reason Pulse hard-gates age $\geq 18$ at patient setup. Separately, this absence was re-verified directly: a case-insensitive search of the complete Pulse engine tree at \texttt{REL\_4\_3\_2} (commit \texttt{e8a3649}) --- physiologically identical to the 4.3.1 pin, the only delta being seven build-system files with no respiratory-source change --- returns zero occurrences of \texttt{surfactant}, and zero of the terms under which such a model would otherwise surface (surface tension, Laplace, derecruitment, alveolar stability, opening/closing pressure); no mention appears in the Pulse engineering forum or the public respiratory methodology. What Pulse reproduces are the macroscopic behaviours surfactant governs, without the underlying surface-tension mechanism: the respiratory model mimics the expected pressure--volume hysteresis of the healthy lung (per Pulse's own respiratory-methodology validation) through a phenomenological compliance curve, and represents alveolar recruitment as an empirical acinar-volume-to-shunt-fraction mapping calibrated to PEEP data rather than as surfactant-governed alveolar stability. Lung compliance is thus a lumped circuit element scaled by disease multipliers with no surface-tension term; neonatal respiratory distress syndrome --- fundamentally a surfactant-deficiency disease, including its response to surfactant instillation --- is therefore not representable in the current lumped-parameter alveolar-compliance model. These are pointers for native pediatric-engine work rather than limitations of the present adult atlas.

\subsection{Provenance of the documented band}\label{sec:s5-prov}

Three convergent boundary probes within the companion technical work (same Pulse v4.3.1 engine, same male reference body, non-overlapping impairment-fraction grids, run-by-run independent execution) characterise the same numerical-bifurcation range in the respiratory solver. A 28-run impairment sweep at ARDSnet-protective ventilation found fractions 0.92 and 0.94 failing to stabilise. A 10-run high-resolution boundary probe at 0.90 / 0.91 / 0.915 / 0.92 / 0.925 / 0.93 / 0.935 / 0.94 / 0.945 / 0.95 narrowed the failure range to 0.91--0.945 inclusive (eight consecutive failures, with 0.90 and 0.95 passing on either side). A complementary 9-run calibration refinement at 0.93--0.97 in 0.005 steps (four failures across 0.93--0.945, five passes across 0.95--0.97) confirmed the upper edge. The three probes are within the same companion project rather than independent third-party replications; the convergence is evidence of reproducibility under the same engine version and reference body, not of generalisation across labs. Pulse's own documentation does not flag this zone.

\textbf{Robustness of the discrete scenario calibration.} The same continuous-severity sweep additionally serves as a robustness check on the four discrete scenario calibration points used by the headline atlas (S1 = 0.00 healthy baseline, S2 = 0.26 mild ARDS, S3 = 0.60 moderate ARDS, S4 = 0.95 severe ARDS). S4 (0.95) was preregistered specifically to sit just above the upper edge of the documented instability band, providing a near-edge stress-test scenario at severe ARDS rather than a robustness-buffered choice --- a deliberate methodological design feature documented in main paper Section~4.3. The atlas's claimed contribution in this domain --- the first public characterisation of the solver-instability band itself (\S\ref{sec:s5-prov}, Section~2.6 of the main paper) --- is a property of the Pulse engine, not of the discrete calibration values that bracket it; the locked S2 / S3 / S4 values are methodological choices anchored to the Berlin Definition PaO$_2$/FiO$_2$ bands and are not presented as headline findings of this work.

\subsection{Two divergence regimes}\label{sec:s5-regimes}

Together with Section~2.5 of the main manuscript, the data distinguish two operationally separate divergence regimes. The input-driven regime (the main-manuscript headline) concentrates on the male reference body at low HR, low SBP, high RR, and FiO$_2$ = 1.0 --- the hypotensive--tachypneic--fully-oxygenated input pattern --- and produces an approximately fivefold higher divergence rate on the male body than on the female. The severity-driven regime (this continuous-severity sweep) affects both sexes at midrange inputs once impairment fraction enters [0.879, 0.945], with female divergence concentrated in the lower part of the band and male divergence in the upper. Both regimes are real solver-stability findings; the sex effect on H3 (Section~2.5 of the main manuscript) is therefore best stated as ``regime-dependent'' rather than ``all-male'', and the practical guidance to downstream users is to avoid the 0.879--0.945 impairment-fraction band when stable steady-state outputs are required.

\section{VC-AC trigger-lockout full protocol}\label{sec:s8}

Section~2.3 of the main manuscript reports that setting Pulse's \texttt{InspirationPatientTriggerPressure} to $-2$~cmH$_2$O on the \texttt{SEMechanicalVentilatorVolumeControl} action collapses the median delivered-tidal-volume coefficient of variation from 0.351 to 0.016 across 64 paired reruns, with 78.1~\% of locked-trigger reruns dropping below the 0.05 steady-state threshold. This supplement section describes the experimental protocol that established the corrective intervention and shows the per-breath waveform evidence that the dyssynchrony signal is real (not a sampling artefact) and that the intervention removes it.

\subsection{Protocol design}\label{sec:s8-protocol}

The 64 paired reruns sampled all eight (scenario, sex) cells, with most coverage concentrated on the healthy-S1 and mild-ARDS-S2 cells where the dyssynchrony signal is densest (Table~1 of the main manuscript). For each rerun, the locked configuration was reproduced exactly from the original sweep, with one and only one modification: the \texttt{InspirationPatientTriggerPressure} field on the VC-AC action was set to $-2$~cmH$_2$O (the trigger-pressure constant declared in \texttt{scripts/run\_s014\_trigger\_lockout.py} and regex-extracted into ledger anchor \texttt{T1.06d.s14\_trigger\_pressure}). All other settings --- Morris input vector, simulation duration, scenario, patient reference body --- remained identical. The intervention is therefore a clean one-parameter manipulation; any change in the steady-state Vt distribution is causally attributable to the trigger-pressure setting.

\subsection{Native 50 Hz waveform evidence (Figure~\ref{fig:s8-vt})}\label{sec:s8-waveform}

Pulse's standard CSV output exposes the delivered tidal volume as a breath-integrated time series sampled at 5-second intervals in the atlas-aggregated parquet. For waveform-level inspection of the trigger dyssynchrony, the native Pulse output (\texttt{output\_pulse\_native.csv} per run) provides the same signal at a 0.02-second sampling interval (50~Hz). At adult respiratory rates of approximately 0.25~Hz (one breath every four seconds), 50~Hz sampling is a 200-fold oversample of the breath-rate signal, well above the Nyquist criterion of approximately $2 \times 0.25 = 0.5$~Hz. The per-breath delivered tidal volume shown in Figure~\ref{fig:s8-vt} is therefore the directly observable breath-by-breath dynamic of the ventilator coupling, not an aliasing artefact.

\subsection{Mechanism and downstream consequence}\label{sec:s8-mech}

The default \texttt{SEMechanicalVentilatorVolumeControl} action in \texttt{AssistedControl} mode enables Pulse's respiratory-model-driven patient trigger when no explicit \texttt{InspirationPatientTriggerPressure} or \texttt{InspirationPatientTriggerFlow} is supplied (\texttt{SEMechanicalVentilatorVolumeControl.cpp} lines 120--128 in the upstream Pulse source). The spontaneous-drive trigger couples breath delivery to the modelled patient respiratory drive and so produces effort-dependent per-breath tidal-volume variance consistent with patient-ventilator asynchrony~\cite{figueroacasas2016} --- physiologically the more faithful regime --- but it breaks the steady-state-mean assumption the locked atlas classifier relies on. Setting the trigger pressure explicitly to $-2$~cmH$_2$O disables the spontaneous-trigger coupling, restoring metronomic breath delivery and dropping the Vt CV by a factor of approximately twenty in the median paired comparison. This is best read as a data-generation / exploration lever, not a clinical recommendation: locking the trigger to a fixed threshold leaves simulated inspiratory efforts below the threshold unrewarded, corresponding in a real patient to a shift from patient-responsive assist-control toward controlled ventilation --- clinically undesirable, and visible only with specialised monitoring such as esophageal pressure or diaphragm electrical activity. Downstream users running atlas-style VC-AC sensitivity sweeps that require deterministic tidal volume can therefore set the trigger pressure explicitly on every action, with that caveat in mind. The patient-ventilator dyssynchrony phenomenon itself is well documented in the clinical literature for real ICU patients on lower tidal-volume volume-control ventilation~\cite{figueroacasas2016}; the present atlas's contribution on this front is the Pulse-engine manifestation of that phenomenon and the $-2$~cmH$_2$O trigger lever for deterministic synthetic-data generation, not the clinical discovery of dyssynchrony itself.

\section{Hyperoxia 300-second convergence full protocol}\label{sec:s9}

Section~2.4 of the main manuscript reports that the locked 120-second simulation window is insufficient for arterial-oxygen-partial-pressure (PaO$_2$) convergence at FiO$_2$ = 1.0 in the healthy S1 cohort: 41 of 44 S1 reruns (93.2~\%) converged to a stable plateau under a 300-second extended simulation, with a converged-subset median PaO$_2$ of 643~mmHg (the per-run plateau median over all 41 drift-converged runs), sitting approximately 20~mmHg below the simple alveolar-gas-equation prediction at sea level of $\approx$~663~mmHg~\cite{west2020respiratory}. \subsection{Practical guidance}\label{sec:s9-guidance}

The kinetic anchor (180 seconds of extended simulation to reach 95~\% of the late plateau on the 38 physiological-converged runs, starting from the saved state at the end of the original 120-second window) gives an objective threshold for downstream Pulse users running hyperoxia simulations: simulating for at least 300 seconds and computing the steady-state mean over the final 60 seconds of that window puts the PaO$_2$ estimate within approximately 5~\% of the asymptote on the healthy cohort. The 120-second window of the locked atlas classifier was appropriate for the cardiovascular and ventilation channels (HR, MAP, Vt, PaCO$_2$ all settle in well under 120 seconds at FiO$_2$ = 1.0) but is the wrong window for PaO$_2$ at the inspired-oxygen boundary; the locked atlas classifier reports the relevant runs as \texttt{implausible} (PaO$_2$ above the 600~mmHg bound) under exactly the conditions where the slow late-phase relaxation has not yet completed.

A separate solver-instability mode emerges only at extended windows on healthy lungs at FiO$_2$ = 1.0: in the S021 cohort, 6 of 44 healthy-S1 reruns (14~\%) developed unphysical PaO$_2$ plateaus above 700~mmHg (four stabilising near 1{,}400~mmHg, above the sea-level barometric pressure of 760~mmHg), all sharing the specific input signature Vt~=~633.3~mL combined with RR~=~20 ($\dot{V}_E \approx 12.7$~L/min, roughly twice the physiological norm of 6--8~L/min). Three of these six stay below the drift threshold and are therefore counted among the 41 drift-converged runs, while the other three are the only three non-converged S1 reruns; the 44 S1 reruns thus partition into 38 physiological-converged, 3 runaway-converged, and 3 runaway-non-converged, and all six runaways are excluded from the physiological median trajectory of Figure~\ref{fig:s9-pao2}. The locked 120-second atlas window terminates these simulations before the runaway emerges; downstream users running extended-window hyperoxia simulations should accordingly avoid Vt $\times$ RR combinations exceeding $\sim$12~L/min minute ventilation on healthy lungs at FiO$_2$ = 1.0.

\section{Sex-stratified blood-volume mechanism: absolute and weight-normalized framings}\label{sec:s10}

Section~2.5 of the main manuscript reports that all 20 of 1{,}280 input-extreme-regime divergences fall on the male reference body, that Pulse's allometric blood-volume formula yields 4{,}802.63~mL for the 67.3~kg male body versus 3{,}996.09~mL for the 56.2~kg female body (a 17~\% absolute-mL sex gap), and that reducing the male reference body's \texttt{BloodVolumeBaseline} toward its 4{,}082.24~mL setup-time floor monotonically eliminates the divergence cluster (20 / 20 $\rightarrow$ 2 / 20 $\rightarrow$ 0 / 20 across 4{,}802.63 / 4{,}400 / 4{,}082.24~mL). This supplement section disentangles the absolute-volume framing from the weight-normalized framing, because the two answer different methodological questions and a reviewer-relevant confounder lives between them.

\subsection{Absolute volumes (the framing used in the main manuscript)}\label{sec:s10-abs}

The Pulse allometric formula~\cite{bray2019} is $\text{BV} = 65.6 \cdot \text{weight}_{\text{kg}}^{1.02}$~mL. On the two reference patient bodies this yields:

\begin{itemize}
\item Male (67.3~kg): $\text{BV} = 65.6 \cdot 67.3^{1.02} = 4{,}802.63$~mL.
\item Female (56.2~kg): $\text{BV} = 65.6 \cdot 56.2^{1.02} = 3{,}996.09$~mL.
\item Absolute-mL difference: $4{,}802.63 - 3{,}996.09 = 806.54$~mL, or 16.8~\% of the male default.
\end{itemize}

The Pulse setup-time floor for the male body sits at 4{,}082.24~mL, 720.39~mL below the male default and 86.15~mL above the female default. The male body cannot be made BV-equivalent to the female body by a one-way \texttt{BloodVolumeBaseline} transplant: the female default sits below the male floor.

\subsection{Weight-normalized volumes (the confounder-controlled framing)}\label{sec:s10-norm}

Comparing absolute blood volumes across patients of different mass conflates intrinsic sex differences with baseline morphological differences. Dividing each absolute BV by the corresponding reference body weight yields the weight-normalized blood-volume index (mL/kg), which controls for the morphological component:

\begin{itemize}
\item Male: $4{,}802.63 / 67.3 = 71.4$~mL/kg.
\item Female: $3{,}996.09 / 56.2 = 71.1$~mL/kg.
\item Weight-normalized difference: $0.3$~mL/kg, or $\approx 0.4$~\% of the male value.
\end{itemize}

The 17~\% absolute-mL sex gap is therefore almost entirely driven by the body-mass difference (67.3 vs 56.2~kg, also a 17~\% gap) rather than by an intrinsic per-kg sex difference in Pulse's allometric BV calculation. This makes methodological sense: the underlying formula $\text{BV} = 65.6 \cdot \text{weight}_{\text{kg}}^{1.02}$ scales blood volume nearly linearly with weight (the 1.02 exponent is close to 1.0), so weight-normalized BV is approximately constant across body masses.

\subsection{Reviewer-relevant disambiguation}\label{sec:s10-disambig}

The atlas's sex-stratified-divergence finding is best stated in absolute-volume terms because the underlying mechanism --- Pulse's setup-time \texttt{BloodVolumeBaseline} floor and the cardiovascular-circuit operating point at that floor --- is parameterised on absolute mL, not on mL/kg. The monotonic divergence-rate reduction from 20 / 20 to 0 / 20 across the 4{,}802.63 $\rightarrow$ 4{,}400 $\rightarrow$ 4{,}082.24~mL dose-response is an absolute-volume effect; it is not what would be predicted from a per-kg physiological sex difference (because there is essentially none).

The same reasoning establishes that the male-vs-female divergence asymmetry in the input-extreme regime is not a claim about per-kg blood-volume physiology in real patients --- it is a claim about how Pulse's internal solver responds to absolute-BV values near its setup-time floor on the male reference body. Pooling male and female Pulse-generated synthetic cohorts in machine-learning pipelines without flag-stratified filtering still introduces a hidden sex covariate at the male reference body's divergence boundary (Section~2.5 of the main manuscript), but downstream users adapting the result to clinical inference should not extrapolate to a per-kg sex-physiology claim that the data does not support.

\section{Engine-side infrastructure recommendations}\label{sec:s11}

Section~4 of the main manuscript closes with a forward-looking note on engine-side infrastructure suggestions for the Pulse maintainers. This supplement section itemises those suggestions as a short numbered list, derived from operating the engine at scale during the 1{,}280-run sweep and the surrounding follow-up experiments. The list is framed as observations from atlas-user experience, not as physiological prescriptions: every item targets tooling, documentation, or validation infrastructure, and each is anchored in a specific experiment from this work. None of the items below recommends changes to Pulse's underlying lumped-parameter physiology, which is the domain of the Kitware biomedical-engineering team.

\begin{enumerate}
\item \textbf{Structured input-rejection events.} Pulse currently surfaces input clamping (e.g.\ SBP $>$ 120, DBP/SBP ratio out of range, HR or RR outside the initialisation band) as \texttt{[ERROR]}-prefixed log lines that downstream tools must regex-parse. A small structured-event API --- one typed record per rejected field, with the offending value, the enforced bound, and the field name --- would let sensitivity-analysis wrappers detect clamping deterministically instead of pattern-matching the four-pattern regex set documented in Supplement~\S\,S3.6.

\item \textbf{Surface the male reference body \texttt{BloodVolumeBaseline} floor in user documentation.} Pulse hard-enforces a 4{,}082.24~mL blood-volume floor at setup on the 67.3~kg / 180~cm male reference body (default 4{,}802.63~mL), but this constant is not currently exposed in the public patient-setup documentation. We discovered it empirically while investigating the all-male divergence cluster (Section~2.5 of the main manuscript); a one-line note in the patient-baseline reference table would have saved the investigation.

\item \textbf{A reference sensitivity-analysis recipe for user-facing operational inputs.} Pulse's repository carries a 2020 \texttt{STUDY\_SENSITIVITY\_ANALYSIS\_1\_0\_0} tag that performs Sobol sensitivity on internal vascular-circuit resistance multipliers for calibration; this is a different parameter class from the user-facing operational inputs (HR, SBP, DBP, RR, Vt, FiO$_2$, PEEP) that sensitivity-conscious downstream users typically need to sweep. A companion recipe --- Morris or Sobol over operational inputs, shipped alongside the existing study --- would give the Pulse community a maintained reference implementation. The atlas's sampler and runner modules are an externally-developed prototype; a maintainer-blessed version would be more durable.

\item \textbf{A setup-time warning for the ARDS impairment-fraction instability zone ($\sim$0.91--0.945).} This instability zone is documented in our preregistration limitations table (Supplement~\S\,S2 row 4) and corroborated by three independent boundary probes (Supplement~\S\,S5.1), but Pulse does not currently emit a setup-time warning when an ARDS action lands in the zone. A single console notice --- ``impairment fraction in reported instability band, results may not be reliable'' --- would prevent downstream users from collecting unusable data without blocking legitimate edge-case research.

\item \textbf{Per-channel steady-state convergence diagnostic in CSV output.} The transient hyperoxia regime characterised in Section~2.4 of the main manuscript (PaO$_2$ still rising at the end of the locked 120-second window at FiO$_2$ = 1.0, with full convergence at $\sim$300~s) suggests that an optional per-output ``drift over final 60~s'' column appended to result CSVs would let users detect non-steady-state runs without writing their own post-processing. The atlas's steady-state classifier already implements exactly this calculation (Supplement~\S\,S3.5); promoting the same diagnostic upstream would generalise it.

\item \textbf{Field-attributed setup-error messages.} Current setup-time blood-pressure and pulse-pressure-ratio rejection messages require some domain knowledge to map back to the offending input field. A one-token prefix indicating which input was rejected (\texttt{[ERROR][SystolicArterialPressure]} rather than the unprefixed text) would let downstream users and continuous-integration pipelines route the message without reading it.
\end{enumerate}

These suggestions are deliberately infrastructure-level: none of them touches Pulse's underlying physiology, ordinary-differential-equation topology, or lumped-parameter assumptions, all of which lie outside the scope of what an external operational-reliability study can credibly prescribe. We share them in the spirit of an open contribution to a shared community tool --- the atlas itself is offered to the Pulse community in exactly the same spirit, and the present paper would have been substantially easier to produce had each of items 1--6 already been in place.

\section{Reproducibility recipe}\label{sec:s12}

The atlas is designed for bit-exact reproduction by an independent investigator. This section documents the minimal end-to-end sequence required to regenerate the canonical 1{,}280-run sweep, the audit ledger, and every quantitative claim in the main manuscript and this supplement. All code, data, and the audit-ledger script are released under the Apache-2.0 license at \url{https://github.com/santinon/pulse_reliability_atlas}.

\subsection{Environment and engine pinning}\label{sec:s12-env}

The atlas pins Pulse v4.3.1 inside a single Docker image (\texttt{pulse-atlas-engine:latest}); the image tag is fixed for the entire 1{,}280-run sweep so that every simulation runs against bit-identical engine binaries. The host environment is Python 3.12+ managed via \texttt{uv} for deterministic dependency resolution. The canonical hardware envelope is a laptop-class machine (MSI laptop; Intel i5-11400H, 6 physical / 12 logical cores; 8~GB RAM; Intel UHD Graphics integrated, plus an NVIDIA GeForce RTX 3050 Laptop GPU (4~GB); Windows 11 Home, version 25H2). Pulse is a CPU-only physiology simulator and neither graphics device is used by the atlas; the discrete GPU is reported here only for completeness so a reader matching the build does not infer CUDA dependence. The parallel-Docker throughput at this envelope is two to three concurrent containers (verified empirically; the canonical sweep was executed with two parallel workers to control thermal load on the laptop chassis).

\subsection{Docker invocation template}\label{sec:s12-docker}

\begin{lstlisting}[

The \texttt{--memory=1g} and \texttt{--cpus=3} caps are safety thresholds that prevent any single Pulse container from saturating the host machine; removing them does not change the simulation output (Pulse is single-threaded per run), only the host's ability to run other workloads concurrently.

\subsection{Three-layer bit-exact verification}\label{sec:s12-verify}

Bit-exact reproduction of the canonical sweep output is verified at three independent layers, each of which can be re-executed from a fresh clone without re-running the full sweep:

\begin{enumerate}
\item \textbf{Canonical Morris sample.} The 1{,}280-row Morris sample is regenerated deterministically from the SALib sampler with \texttt{trajectories = 20, levels = 4, seed = 42}; the regenerated sample matches the committed \texttt{data/runs/full\_sweep/morris\_sample.parquet} byte-for-byte.
\item \textbf{Per-cell aggregate parquets.} The 8 per-cell aggregated parquets (\texttt{data/runs/full\_sweep/<scenario>\_<sex>/aggregated.parquet}) reproduce identically when the full sweep is re-executed against the pinned Docker image on the canonical compute envelope.
\item \textbf{Derived statistical artefacts.} The Morris $\mu^{*}$ indices, bootstrap confidence intervals, Wasserstein distances, Spearman correlations, and BH-FDR survivors all regenerate bit-equivalently from the canonical aggregated parquets; this is what the audit ledger (\texttt{scripts/audit\_claims.py}) re-derives at every run.
\end{enumerate}

The audit ledger is the primary reproducibility instrument: a green ledger run (247/247 PASS) confirms that every quantitative claim in the main manuscript and supplement is consistent with the canonical artefacts. A failed claim is a structured triage item (Type A transcription drift, Type B orphaned number, Type C derivation mismatch) with a precise file:line pointer for forensic tracing.

\subsection{Independent reproduction on separate hardware}\label{sec:s12-independent}

Beyond the three-layer re-derivation above --- which regenerates the analysis from the committed canonical artefacts --- the end-to-end pipeline was independently re-executed from scratch by a co-author (Y.M.) on a second x86\_64 host --- an AMD Ryzen~5 CPU running Linux under WSL2 --- distinct from the canonical Intel x86\_64 / Windows reference environment.

First, the full 1{,}280-run Morris sweep was re-run there (two parallel Docker workers; wall time 23~h~01~m). All five run-level flags matched on 1{,}280/1{,}280 runs, every continuous steady-state value was bit-identical, and only three derived H4 statistics differed at $\sim 10^{-14}$ floating-point round-off, with an identical Benjamini--Hochberg false-discovery-rate survivor set.

Second, the 22-run S1\_M pilot was re-run on the same host with per-run output capture. Its aggregate was bit-identical to the canonical pilot ($\max |\Delta| = 0$ across all six channel means) with 100\,\% five-flag concordance on 22/22 runs.

Both reproductions are archived under \texttt{audits/}: \texttt{reproduction\_2026-06-07/} carries the reproduced full-sweep aggregate, the derived analysis outputs, and a numerical comparison report (\texttt{reproduction\_check\_2026-06-07.md}); \texttt{reproduction\_thinkpad\_2026-06-10/} carries a provenance README (host, Docker image tag and digest, pinned Pulse v4.3.1, exact commands), the 20 per-run output CSVs, and the comparison tables.

\subsection{Reproducibility scope and limits}\label{sec:s12-scope}

The verification and the independent reproductions above span the Intel x86\_64 reference environment and a second, AMD x86\_64 host (Linux/WSL2), all bit-identical --- empirical evidence that bit-identity holds across CPU vendor and host operating system within the x86\_64 family. Cross-\emph{architecture} reproduction --- for example, x86\_64 $\rightarrow$ Apple Silicon ARM64 --- was not empirically tested in the present work and remains future work. Bit-identity within the same architecture family is expected given Pulse's fixed 20~ms ODE timestep and standard math-library usage, and is now empirically supported across two x86\_64 CPU vendors; cross-architecture bit-identity is plausible but not guaranteed without explicit verification. Image immutability is currently anchored at the Docker tag level (\texttt{pulse-atlas-engine:latest} plus the pinned Pulse v4.3.1 Git tag); for archival re-execution five or more years from now, cryptographic digest pinning (\texttt{@sha256:...}) of the Docker image is the more robust mechanism and is recommended for any such future re-execution attempt.

\section{SHAP cross-verification of the Morris sensitivity rankings}\label{sec:s13}

The locked \texttt{not\_steady\_state} flag fires on 530 of 1{,}280 runs across the full sweep; Supplement~\S\,S4 decomposes that 530 into the three contributing sub-modes (SpO$_2$-saturation pinning, VC-AC tidal-volume dyssynchrony, and a residual dominated by severe-ARDS slow convergence and FiO$_2$ = 1.0 transient hyperoxia). This section adds a complementary cross-verification: an independent machine-learning analysis recovers the same input-importance rankings that the preregistered Morris elementary-effects design establishes, by a different statistical route and on a different subset of the data.

\subsection{Methodology: epistemological scope}\label{sec:s13-scope}

The Morris elementary-effects design is interventional: each trajectory perturbs one input at a time along a fixed grid, so the resulting $\mu^{*}$ ranking is a causal-mechanistic statement about how Pulse responds to deliberate perturbations of each input. By contrast, a SHAP analysis~\cite{lundberg2017} on a tree-based reference body model trained on the observational distribution of Morris outputs is a fundamentally different statistical object: it summarises how a black-box predictor associates input features with output predictions, on the data distribution as actually observed. The two methods answer different questions, and the load-bearing analysis in this work is the interventional Morris design --- the SHAP analysis is included only as a secondary cross-verification.

\subsection{Cross-verification result on the clean subset}\label{sec:s13-result}

A supplementary RandomForest regressor + SHAP feature-importance ranking was computed on the $n = 663$ clean-subset rows (the runs with no \texttt{clamped}, \texttt{diverged}, \texttt{implausible}, or \texttt{not\_steady\_state} flag), separately per output and per (scenario, sex) cell. The SHAP-top-3 input ranking was then compared against the Morris-$\mu^{*}$-top-3 ranking on the same cells. Three summary statistics characterise the agreement:

\begin{itemize}
\item \textbf{17 of 18 pooled (output $\times$ top-3) cases agree} at the full 3-of-3 ranking level (ledger anchor \texttt{T2.s023.pooled}).
\item \textbf{23 of 48 per-cell (scenario $\times$ sex $\times$ output) cases agree at the full 3-of-3 level} (ledger anchor \texttt{T2.s023.fullmatch}).
\item \textbf{90~\% of per-cell comparisons agree at $\geq$ 2-of-3 level} (43 of 48; ledger anchor \texttt{T2.s023.ge2\_pct}).
\end{itemize}

\subsection{Interpretation}\label{sec:s13-interp}

The strong pooled-level agreement (17 of 18) is the load-bearing cross-verification: a SHAP analysis on the clean-subset data distribution recovers the same dominant inputs that the interventional Morris design identifies, on six independent outputs. The lower per-cell full-match rate (23 of 48) is expected, because per-cell sample sizes (42--144 clean runs per cell) are smaller and the SHAP ranking depends on the observed input-output distribution within that cell, which is heavily influenced by which Morris trajectories happened to land on clean runs. The 92~\% $\geq$ 2-of-3 agreement at the per-cell level is the appropriate level of comparison: a top-3 ranking is preserved if SHAP recovers two of the three inputs the Morris design ranks first.

The SHAP cross-verification works because the underlying physiology is real, not the other way round. Morris establishes the mechanistic input-importance ranking through a preregistered one-at-a-time perturbation design; SHAP independently recovers the same ranking by a different (data-driven, observational, tree-based) route. The agreement is evidence that the Morris-derived rankings are not artefacts of the elementary-effects design --- they correspond to input dependencies that any reasonable statistical method would identify on the same data.

\section{Compensatory tachycardia: input HR vs output HR under hypoxemia}\label{sec:s15}

Section~2.6 of the main manuscript reports that, under increasing ARDS severity, Pulse's output heart rate decouples from the user-specified input HR baseline as the engine's documented baroreceptor and chemoreceptor reflexes assert themselves against severe arterial hypoxemia. This supplement section provides the per-scenario quantitative breakdown that establishes the decoupling and the operational-interpretation guidance for Morris elementary-effects on input HR.

\subsection{Mechanism and Morris-EE interpretation}\label{sec:s15-mechanism}

In S1 (healthy lungs), Pulse settles output HR near a physiological norm of approximately 74~bpm regardless of the user-requested input baseline --- the requested HR is achieved without compensatory engagement because oxygenation is adequate. By S3 (60~\% alveolar impairment) and S4 (95~\% alveolar impairment), the engine's documented baroreceptor and chemoreceptor reflexes drive output HR into the 145--160~bpm range despite identical input sampling, an approximately 70~bpm sympathetic overshoot above the $[50, 110]$~bpm input-range midpoint, whose magnitude reflects the severity of arterial hypoxemia rather than the input baseline. The compensation is strong enough to dominate the explicit input HR baseline. Notably the overshoot is non-monotonic in severity: as Table~\ref{tab:s15-comphr} shows, output HR peaks at S3 (moderate) and eases at S4 (severe), plausibly reflecting incipient cardiovascular decompensation at 95~\% alveolar impairment, where sustained maximal sympathetic drive can no longer be maintained.

The operational consequence for Morris elementary effects on input HR in the ARDS scenarios is that the measured $\mu^{*}$ on output HR captures the coupling between compensation gain and input setting, not the steady-state effect of a resting heart rate. The H1 result that cardiovascular outputs are HR-dominated remains robust; the interpretation, however, is that ``the compensation responds proportionally to the input baseline'' rather than ``the input HR is the steady-state HR.'' Users running Pulse for ARDS device-validation should treat output HR as the engine's reflex response to the active scenario, not as a setpoint imposed by the input.
